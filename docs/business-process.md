# Бизнес-процессы онлайн-ателье

В учебной работе представлены три BPMN 2.0 модели с графическими координатами:
- [Продажа готовой одежды](catalog-sales.bpmn)
- [Индивидуальный пошив](custom-tailoring.bpmn)
- [Отмена, возвраты и склад](order-cancellation.bpmn)

## Продажа из каталога

```mermaid
flowchart TD
 A["Открыть бот / Mini App"] --> B["Категория, размер, цвет"]
 B --> C["Корзина"] --> D["Контакты и получение"]
 D --> E{"Всё в наличии?"}
 E -- "Нет" --> B
 E -- "Да" --> F["Заказ + атомарное списание остатков"]
 F --> G["Уведомление менеджера"]
 G --> H["Подтверждение"] --> I["Подготовка / изготовление"]
 I --> J["Отправка / выдача"] --> K["Завершение"]
 ```

Автоматизация: запись заказа, проверка товара, сохранение
исторической цены, изменение статусов, уведомления и отчёты.
Менеджер отвечает за физическую отправку, расчёт фактической
себестоимости, проверку денег и фактический возврат.

## Индивидуальный пошив

```mermaid
flowchart TD
 A["Пожелания, мерки, фотографии"] --> B["Заявка"]
 B --> C["Ручная оценка затрат и цены"]
 C --> D{"Клиент согласен?"}
 D -- "Нет" --> E["Отмена заявки"]
 D -- "Да" --> F["Подтверждение версии сметы"]
 F --> G["Производство"] --> H["Выдача / доставка"]
 H --> I["Завершение"]
 ```

Подтверждение сметы не означает проведение платежа.
Прежняя версия сметы после пересчёта считается недействительной.

## Отмена и склад — согласованное правило реализации

```mermaid
flowchart TD
 A["Запрос отмены"] --> P{"Нет незакрытой оплаты?"}
 P -- "Нет" --> Q["Сначала вручную зарегистрировать денежный возврат"]
 P -- "Да" --> B["Статус canceled + запись в историю"]
 B --> C{"Изделие уже отправлено?"}
 C -- "Нет" --> D["Автоматический возврат остатка на склад"]
 C -- "Да" --> E["На складе пока ничего не добавлять"]
 E --> F{"Физически принято обратно?"}
 F -- "Нет" --> G["Ожидать реального возврата"]
 F -- "Да" --> H["Акт через /return ID ПОЛУЧЕНО или панель"]
 H --> I["Восстановление остатка один раз"]
 ```

БД гарантирует, что отмена до отправки не дублирует возврат товара,
а после отправки новый остаток возникает только вслед за отдельным
подтверждённым актом. Повторную запись акта по тому же заказу
запрещает уникальный индекс. Реальные перемещения товара и
сверка с физическим складом выполняются менеджером, а не ботом.

## Что анализирует система

- Количество заказов по текущим статусам и типу.
- Цена и себестоимость завершённых заказов; **валовая**, не чистая прибыль.
- Учётные денежные поступления и возвраты отдельно от стоимости заказов.
- Остатки и SKU, позиции с низким запасом.
- История изменения статусов и дата обработки.
- Отдельно — факт возврата изделия после отправки.

## Оценка результата

Система автоматически фиксирует заявки и не требует переписывать их
в Excel вручную. Но экономия рабочего времени, рост конверсии и
снижение фактических ошибок склада должны проверяться на
сопоставимых реальных сценариях, не выводиться из одних тестов кода.
