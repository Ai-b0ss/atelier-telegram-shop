# Развёртывание и приёмочные испытания

## Фактическая демо-приёмка 1 ноября 2026

Бот [@atelier_customwear_2611_bot](https://t.me/atelier_customwear_2611_bot) создан через BotFather, токен сохранён только в локальном `.env`. ID администратора получен по ответу настоящего Telegram API на `/start`. Демонстрационный режим `DEMO_MODE=1` ограничивает операции только администратором.

Из Telegram Desktop реально пройдены каталог, корзина, оформление тестового заказа №1, уведомление менеджера, отмена и получение Excel. В SQLite подтверждено: заказ отменён, остаток восстановлен (5 шт.), платежей нет. Это **живой локальный тест**, а не боевой запуск для покупателей. При отключении ПК или завершении polling-процесса бот перестанет отвечать; для постоянной работы нужен управляемый хостинг.

## Что можно выполнить без Telegram

1. `python -m pytest -q` — проверить доменную логику, Excel и офлайн-сценарии обработчиков Telegram.
2. `python -m atelier.seed` — создать локальный демонстрационный каталог (`DATABASE_PATH`, по умолчанию `data/atelier.sqlite3`).
3. `python -m atelier.manage list` — убедиться, что товары созданы.
4. `python -m atelier.export reports/first-report.xlsx` — проверить отчёт. При повторном запуске выбрать новый файл.
5. `python -m atelier.backup backups/first-copy.sqlite3` — проверить резервную копию.
6. `python -m atelier.demo out/demo` — создать независимую учебную базу из трёх заказов и Excel-файл.

**Внимание:** демонстрационные данные не должны считаться реальными клиентскими товарами, ценами или поступлениями.

## Локальная эксплуатация в Windows — 1 ноября 2026

Установлена задача Windows Scheduler `AtelierTelegramDemo` для текущего
пользователя. На входе в Windows запускается супервизор `atelier.supervisor`,
который запускает один polling-бот, восстанавливает его после падения и делает
SQLite-снимки каждые 6 часов. Во время проверки был принудительно завершён
бот-процесс; журнал подтвердил его автоматический перезапуск.
Сначала было обнаружено, что штатная остановка Планировщика оставляла Python-бота сиротой. После исправления добавлен Windows Job Object с `KILL_ON_JOB_CLOSE`: тест на Windows и реальная остановка задания подтвердили отсутствие оставшихся процессов. Новый task затем успешно запущен.

Повторная попытка отдельного `python -m atelier` была отвергнута
`atelier.polling.lock`, без конфликта getUpdates.

Используйте `data/logs/supervisor.log` для диагностики.
В `data/backups` автоматически накапливаются копии; перед реальной
эксплуатацией настройте удаление/архивацию с учётом приватности.
Супервизор не переживает выключение компьютера, выход из пользователя
и отсутствие интернета; это не замена VPS.

## Windows: безопасная локальная настройка

В каталоге проекта выполните `scripts/setup-bot.ps1` для однократного ввода токена BotFather (скрытый ввод) и числового Telegram ID администратора. Скрипт запрещает перезапись существующего `.env` и проверяет, что Git его игнорирует. После настройки запускайте `scripts/start-bot.ps1`. Все команды запускаются внутри собственного окружения `.venv`. Токен и файлы реальных клиентов не должны попадать в публичный репозиторий.

## Запуск с Telegram

1. Создать бота через официальный @BotFather, получить новый токен. Не размещать токен в переписке, скриншотах, Git или отчётах.
2. Указать токен в локальном `.env` как `BOT_TOKEN`, а личный числовой Telegram ID менеджера — в `ADMIN_IDS`.
3. Установить Python 3.11+ и зависимости из `requirements.txt` либо использовать Docker Compose.
4. Запустить бота по README. Один и тот же токен не должен использоваться одновременно в нескольких экземплярах long polling.
5. На отдельном тестовом аккаунте пройти `/start` → каталог → корзина → оформление заказа, проверить уведомление администратора.
6. Администратору проверить `/orders`, фильтры, `/order`, смену статусов, `/stats`, `/report`. Убедиться, что неавторизованный аккаунт получает отказ.
7. Создать тестовую заявку на пошив, отправить смету `/quote`, затем переотправить новую смету с **той же ценой**, убедиться, что старая кнопка отклонена, а новая работает.
8. Создать тестовую ручную запись оплаты и возврата с уникальными банковскими номерами, убедиться, что повторное внесение того же номера заблокировано; сверить Excel.
9. Проверить остановку/повторный запуск, сохранность базы, восстановление из резервной копии.

**Не проводить реальные платежи ради теста.** `/payment` лишь отражает факт поступления, проверенный менеджером, и не принимает деньги.

## Cloudflare webhook-хостинг

Инфраструктура подготовлена в `cloudflare/`: публичный Worker, D1 и шаблоны
развёртывания. Сейчас Cloudflare не принимает обновления от Telegram:
`BOT_TOKEN`, `ADMIN_IDS`, `WEBHOOK_SECRET` не переданы в Worker Secrets.
Локальный polling оставлен работающим, чтобы не потерять доступность бота.
Переключение требует завершения секретной настройки и проверки `getWebhookInfo`.
Не путать доступность `/health` с полноценным переключением Telegram.
Подробнее: [Cloudflare README](../cloudflare/README.md).

## Эксплуатационные ограничения

- SQLite + long polling предназначены для одного запущенного экземпляра бота, а не кластера из нескольких процессов.
- `.env`, `data/`, файлы отчётов и резервных копий содержат чувствительные сведения; доступ к ним нужно ограничить.
- Команда `/forgetme` удаляет персональные сведения из рабочей БД, однако старые резервные копии, журналы оператора и ранее скачанные Excel-файлы необходимо учитывать отдельно в политике хранения и удаления.
- Для реальных покупателей нужны юридически корректные условия обработки персональных данных и порядок работы с возвратами, оплатой и учётными документами.
- При ошибке токена перезапускать бот с корректным токеном, не менять исходный код и не публиковать `.env`.
- Живой тест Telegram API проведён на административной учётной записи; отдельная приёмка с другим покупателем ещё нужна.
