# Подбор инструментов для редизайна Telegram Mini App ателье

Исследовано 01.11.2026. Задача: сделать магазин авторской одежды
достаточно выразительным, чтобы он запоминался, но не ухудшить выбор
товара, контроль размеров, доверие и оформление заказа.

Текущая архитектура: **Cloudflare Workers + D1; статические
HTML, CSS, JS** в `cloudflare/public/`; Telegram WebApp API через
`telegram-web-app.js`. Без React, Vite и Tailwind. Основная
серверная логика подтверждена тестами, поэтому редизайн не должен
менять её без отдельного обоснования. На сайте сейчас три вымышленных
изделия и только одна Telegram-фотография на товар; нет реального
коммерческого режима.

**Статус этой подборки:** проверены README, GitHub-лицензии,
даты обновления и применимость; ничего из внешних репозиториев пока
не устанавливалось и не исполнялось. Здесь ссылки и критерии выбора,
а не заявление о завершённой интеграции.

### Отложить / не ставить без причины

- [Taste](https://github.com/LeonxLnx/taste-skill) — мощная альтернатива
  Hallmark с реальными изображениями и браузерным QA (MIT, Node 22+).
  Из README: полный цикл до 30–45 мин и большой расход контекста;
  не включать одновременно в основной маршрут с Hallmark и
  Impeccable без разрешения противоречий.
- [TelegramUI](https://github.com/telegram-mini-apps-dev/TelegramUI)
  — React-компоненты, MIT, но пришлось бы переносить существующий
  JavaScript-проект на React. Сейчас неоправданно.
- [redesign-skill](https://github.com/elayadesign/redesign-skill)
  — для уже работающего приложения, MIT, но предписывает жёсткую
  готовую палитру, строго запрещает определённые шрифты и навязывает
  градиентный заголовок. Использовать как аудит, а не как авторитет
  над фирменным стилем.
- [one-shot-ui](https://github.com/TN0123/one-shot-ui) и
  [Design Lens](https://github.com/mojomoth/design-lens) —
  перспективные инструменты извлечения дизайна со скриншотов,
  но маленькая база пользователей. Только отдельная песочница
  после проверки поведения и лицензии.
- Комбайны на 30–40+ скиллов не ставить «на всякий случай»:
  больше конфликтующих инструкций, дороже контекст, сложнее аудит.
- `Lenis`, full-screen WebGL, автоплей loop-анимаций,
  тяжёлые React-наборы и игровой UI не соответствуют текущей
  задаче каталога одежды.

## 3. Подключение — только после выбора концепции

**Безопасный порядок:** прочитать LICENSE и SKILL.md конкретной версии
и проверить команды/сетевые запросы → установить один агентский скилл
в проект, не глобально → вызвать только его аудит и сформировать DESIGN.md
→ проверить изменения и ограничения → переходить к следующему слою.

Проверенные upstream-команды как справка (НЕ исполнять все разом):

```sh
# Inspo: только показать предлагаемые изменения конфигурации
npx -y inspo-mcp install --dry-run
# Claude Code: подключить бесплатный официальный hosted endpoint Inspo
claude mcp add --transport http inspo https://inspomcp.dev/api/mcp
# Impeccable: проектный установщик; сначала изучить пакет
npx impeccable install
# Hallmark: только одна выбранная агентская конфигурация
npx skills add nutlope/hallmark --agent codex
# Vercel: технический аудит, без React-зависимости
npx skills add vercel-labs/agent-skills --skill web-design-guidelines
# Emil Kowalski: точечный навык движения
npx skills add emilkowalski/skills --skill review-animations
```

Для новых внешних команд нужны зафиксированные версии/commit SHA
и тестовая среда. Не пересылать ни BotFather токен, ни Cookie,
ни персональные данные покупателей в сторонние дизайн-сервисы.

## 4. Результат для продаж: не цвет, а путь пользователя

Рекомендации [Baymard Apparel UX](https://baymard.com/research/apparel-and-accessories)
и [Product Page UX 2026](https://baymard.com/research-articles/current-state-ecommerce-product-page-ux):

1. С первого экрана видно изделие, его вид на человеке, цену и
   сценарий получения. Не закрывать товар визуальной метафорой бренда.
2. Размеры — явными кнопками с состоянием доступности, а не
   скрытым выпадающим списком; нужна подсказка по посадке и меркам.
3. Изображения должны честно показывать ткань, размер и форму,
   позволять увеличить детали и переключить ракурсы.
4. Рядом с заказом — срок изготовления и понятные условия
   доставки/возврата (только реальные данные, не выдумывать).
5. Корзина и форма пошива — короткие, предсказуемые, с сохранением
   заполненного, явными состояниями ошибок и повторных запросов.
6. Уникальность — типографика, реальные фотографии, материал,
   композиция, одна фирменная микроанимация (если она помогает).
7. Проверять конверсию можно только на реальных допустимых тестах
   после запуска; в текущем `DEMO_MODE=1` реальных покупателей нет.

## 5. Конкретный маршрут в следующей задаче

**A. Изучить 3 референса:** 2–3 сайта fashion/atelier через Inspo,
нужны мобильные скриншоты и измеримые токены. Один редакционный,
один экспериментальный, один с хорошо оформленным заказом.

**B. Утвердить визуальное направление:** 2–3 концепции
на одном ассортименте (пока заведомо синтетическом), не копировать
ни чужие изображения, ни торговые марки.

**C. Фиксировать структуру в `docs/DESIGN.md`:**
цветовые роли, шрифты и лицензии, типографическая шкала,
контейнеры, отступы, кнопки, поля, состояния, навигация, motion.

**D. Сделать редизайн в отдельной ветке:** сначала каталог и карточка
товара, потом корзина и пошив, потом админка. Не менять API и
бизнес-логику только ради внешнего вида.

**E. Проверить:** Playwright screenshot diffs 375/390/430/768/1440,
axe-core, отсутствие горизонтальной прокрутки, reduced-motion,
ручной сценарий в Telegram iOS/Android, 48 Python и все Node-тесты.

**F. Выложить только после сравнения до/после.**
Платежи и боевой режим не включать.

## 6. Что найдено в личной библиотеке

`/ДАННЫЕ_ДЛЯ_ДИЗАЙНА.md`, 29.10.2026, описывает не ателье,
а TravelTech. Оттуда полезны противодействие «нейрослопу»,
дисциплина токенов, мобильная верстка и ссылки на Hallmark,
Taste, redesign-skill, Inspo и Rune Icons. Запрет на определённые
пары шрифтов и требования к TravelTech-палитре **не являются**
техническими обязательствами для ателье.

### На что опирались при проверке
GitHub README/LICENSE и последние push по официальным репозиториям
Impeccable, Hallmark, UI/UX Pro Max, Emil, Inspo, Taste,
Motion, PhotoSwipe, Embla, Telegram Mini Apps, Pixelfx,
Rune Icons, Vercel Guidelines, Playwright, axe-core;
официальные docs Motion/TMA SDK/Baymard. GitHub-проекты
не считались надёжными лишь по числу звёзд.

**Итоговый компактный набор:** Inspo (референсы) →
Impeccable (план и критика) → Hallmark **или** Taste
(разработка направления) → Vercel/Playwright/axe
(проверка) → Motion mini + PhotoSwipe
(необходимые улучшения). PixelFX — опциональный эксперимент.
