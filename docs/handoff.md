# Передача проекта другому агенту/разработчику

**Назначение:** Telegram-магазин авторской одежды: каталог/корзина/заказы/индивидуальные заявки, ручной финансовый учёт, Excel.

**Состояние на 31 октября 2026 года:** публичный GitHub-репозиторий https://github.com/Ai-b0ss/atelier-telegram-shop опубликован. Ветка main, история сохранена. На Windows созданы виртуальное окружение и локальная копия; 45 тестов, импорт aiogram и генерация демонстрационного Excel прошли. GitHub Actions (Python 3.11, 3.12, 3.13) прошли на повторном запуске после перевода репозитория в публичный. Telegram-бот создан, демонстрационный хостинг перенесён в Cloudflare Workers + D1; эксплуатация с настоящими клиентами пока не разрешена.

## Структура

- `atelier/store.py` — SQLite и транзакции для заказов, резервов склада, оплаты, статусов, обезличивания.
- `atelier/bot.py` — обработчики aiogram 3, клиентская и административная часть.
- `atelier/reports.py` — выгрузка Excel, отдельные денежные показатели, защита строк от формул.
- `atelier/manage.py` — управление ассортиментом без Telegram.
- `atelier/seed.py`, `atelier/export.py`, `atelier/backup.py`, `atelier/demo.py` — демонстрационный ассортимент, автономный отчёт, резервное копирование и воспроизводимый показ системы.
- `docs/` — бизнес-процессы, BPMN, ER, инженерный отчёт, результаты тестов и развёртывание.
- `tests/test_store.py`, `tests/test_bot_offline.py` — 45 тестов: имитация обработчиков, а также реальный диспетчер aiogram 3 с перехваченным сетевым API.

## Безопасность решений

- База SQLite хранит все суммы в целых копейках, цены позиций заказов фиксируются снимками, остатки проверяются под `BEGIN IMMEDIATE`.
- Деньги и возвращённые суммы записываются вручную, банковской интеграции нет; номер операции может блокировать её повторную запись. Сумма всех закрытых продаж отделена от полученных денег.
- Возврат товара на склад производится автоматически только при отмене до отправки. После отправки необходим ручной осмотр фактического возврата.
- При `/forgetme` персональные контакты, мерки и свободные комментарии к платежам из закрытых заказов обезличиваются, суммы платежей сохраняются. Старые резервные копии не очищаются автоматически.
- Административные команды защищены списком числовых Telegram ID. Все диалоги — личные.

## Проверено

- Локальная среда Python 3.13: 45/45 тестов pytest, `compileall`, Excel, проверка BPMN XML; без реальной сети Telegram.
- SQLite backup/restore и невозможность переписать существующий файл в автоматизированных тестах.
- Локальный прогон 50 полных заказов — 0,795 с на операции БД, отчёт 25,0 мс. Не является нагрузочным тестом Telegram.

## Непроверенное и незавершённое

1. В Windows-окружении aiogram установлен и успешно импортируется, но взаимодействие с настоящим Telegram API пока не проверено.
2. Для настоящего запуска нужны токен от BotFather, `ADMIN_IDS` и внешний хостинг/ПК с активным процессом.
3. GitHub CLI авторизован с разрешениями repo и workflow, использует автоматически обновляемый токен. Репозиторий публичный. GitHub Actions: https://github.com/Ai-b0ss/atelier-telegram-shop/actions/runs/41226924664 (успешно).
4. Для продакшена нужен юридический и организационный контроль обработки персональных данных, платежей, возвратов, хранения данных, а также систематические резервные копии.

## Надёжный Windows-демозапуск

На 1 ноября установлен task `AtelierTelegramDemo` (при входе пользователя). `atelier.supervisor` запускает polling и восстанавливает его после сбоя; проверено завершением дочернего процесса. Снимки SQLite — на старте и каждые 6 часов, в `data/backups`, без удаления старых. Одновременный polling блокирует `atelier.polling.lock`. Для диагностики `data/logs/supervisor.log`; код задач в `scripts/install-windows-autostart.ps1`. Хостинг не 24/7, база и токен только локально.

При остановке Windows Task Scheduler дочерние процессы бота раньше оставались сиротами. Исправлено через `atelier/windows_job.py` (Job Object / KILL_ON_JOB_CLOSE), проверено реальным stop/start задания: после остановки не осталось ни одного polling-процесса.

## Этапы комплексного развития (1 ноября 2026)

- Заказы D1: в миграции `0001_order_status_triggers.sql` включены два
  триггера — история изменения статуса и возврат stock в одной SQL
  транзакции при `status -> canceled`. JS не делает второй возврат.
- `cloudflare/src/auth.js`: Telegram Mini App auth HMAC (подпись,
  auth_date <= 10 минут, admin allowlist). Административные API закрыты.
- `cloudflare/src/api.js`: каталог, корзина, идемпотентный checkout,
  индивидуальная заявка, операции администратора, отчётность и настройки.
- `cloudflare/public/`: адаптивная витрина, форма пошива, панель
  администратора с товарами, остатками, заказами, аналитикой и реквизитами.
  Запущено на `/app` и `/admin`; меню Mini App настроено в Telegram.
- Фото товара: `/photo ID` в Telegram, открытие из админки, прокси
  `GET /media/product/ID`. Фото-референсы пошива (до 4) сохраняются
  по Telegram file_id в `custom_attachments` и отправляются мастеру.
- `migrations/0002_miniapp.sql` и `0003_store_readiness.sql` —
  схема для идемпотентности, фото и юридических данных.
- Ежедневная очистка технических записей через Cron без удаления заказов.
- Коммерческий режим заблокирован двумя переменными `DEMO_MODE=1`
  и `STORE_READY=0`. Настоящие платежи, каталог продавца,
  договорные условия и отдельная двухпользовательская приёмка не готовы.
