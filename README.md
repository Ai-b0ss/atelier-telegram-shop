# Atelier Telegram Shop — бот для авторской одежды

Учебный, но запускаемый MVP продажи авторской одежды через Telegram: **каталог → корзина → оформление заказа**, индивидуальные заявки на пошив, административные статусы, ручной учёт финансовых операций и Excel-отчёты.

## Возможности

- Категории, товары, размеры, цвета и складские остатки; фотографии по Telegram `file_id`, если указаны в базе.
- Корзина с проверкой наличия и атомарным оформлением заказа (SQLite).
- Заявки на индивидуальный пошив с мерками и пожеланиями; согласование точной версии сметы, защищённое от устаревших кнопок и гонок.
- Администраторские команды для статусов, смет, записи оплат и возвратов; необязательный уникальный идентификатор платежа для защиты от двойной записи.
- Excel (.xlsx): сводные показатели, заказы, платежи, остатки и учётная себестоимость.
- 34 автоматических теста, включая офлайн-проверку обработчиков бота, финансов, остатков, конкуренции, приватности, резервных копий и выгрузки.
- Меню фильтрации заказов, кнопки изменения статусов и `/stats` для администратора.
- `/privacy`, `/forgetme`: информация о данных и запрос обезличивания после закрытия заказов.
- Автономный экспорт в Excel и согласованные резервные копии SQLite (без Telegram).

## Запуск

Требуется **Python 3.11+** и токен Telegram от @BotFather.

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\\Scripts\\Activate.ps1
pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env`. Заполните **BOT_TOKEN**, **ADMIN_IDS** (Telegram ID администратора через запятую), при желании **DATABASE_PATH**. Переменные из `.env` нужно загрузить в окружение, например:

```bash
# Linux/macOS:
set -a; source .env; set +a
python -m atelier.seed
python -m atelier
```

Windows PowerShell:

```powershell
Get-Content .env | Where-Object { $_ -match '^[A-Z_]+=' } | ForEach-Object {
  $key,$value = $_ -split '=',2
  [Environment]::SetEnvironmentVariable($key,$value,'Process')
}
python -m atelier.seed
python -m atelier
```

Или через Docker Compose (после создания `.env`):

```bash
docker compose run --rm bot python -m atelier.seed
docker compose up -d --build
```

**Важно:** демонстрационные товары вымышленные. Перед продажей замените ассортимент и цены в SQLite, укажите администратора и настройте хостинг для круглосуточного запуска. Для изменения каталога предусмотрена консольная утилита `python -m atelier.manage` (см. ниже), графической админ-панели пока нет.

## Настройка каталога

```bash
python -m atelier.manage list
python -m atelier.manage category "Платья"
python -m atelier.manage product 4 "Платье с вышивкой" "Лён, ручная вышивка"
python -m atelier.manage variant 4 DRESS-S-BLUE S синий 9500 4200 5
python -m atelier.manage stock 4 7
python -m atelier.manage deactivate 4
```

Числа `4` — примеры идентификаторов: после создания посмотрите фактически возвращённый ID. Цены указываются в рублях. Загрузка фото использует Telegram `file_id`: `python -m atelier.manage photo <product_id> <file_id>`.

## Пользовательские сценарии

`/start` → категории → изделие → размер/цвет → корзина → оформление → имя, контакт, адрес / самовывоз.

`/start` → «Индивидуальный пошив» → описание → мерки → контакты → заявка. Стоимость такого заказа изначально нулевая и **не означает бесплатный пошив**: менеджер задаёт смету, после чего клиент может принять или отклонить предложение кнопкой в Telegram. Устаревшие кнопки с прежней ценой не работают.

`/cancel` прерывает ввод. «Мои заказы» показывает только заказы текущего Telegram-пользователя.

## Команды администратора

| Команда | Назначение |
|---|---|
| `/admin` | подсказка |
| `/orders` | последние 30 заказов |
| `/orders new` | заказы выбранного статуса |
| `/order 12` | детали заказа и контактные данные для менеджера |
| `/quote 12 15000 8500` | смета индивидуального заказа №12: цена и себестоимость в рублях |
| `/status 12 confirmed` | перевод заказа в разрешённый следующий статус |
| `/payment 12 received 3000 BANK-001` | **ручная запись** подтверждённого поступления 3000 ₽; `BANK-001` — уникальный номер операции (необязательно, но рекомендуется) |
| `/payment 12 refunded 3000` | **ручная запись** подтверждённого возврата 3000 ₽ |
| `/report` | Excel-выгрузка |
| `/stats` | Денежные поступления, завершённые продажи, себестоимость и валовая маржа |

Статусы: `new`, `confirmed`, `in_production`, `ready`, `shipped`, `completed`, `canceled`.

**Бот не принимает реальную оплату и не переводит деньги.** Команда `/payment` вносит запись только после сверки с реальным платежом. Уникальный банковский номер препятствует двойному учёту одной операции; без него администратор должен сам проверить дубликаты. Нельзя отменить заказ с невозвращённой оплатой.

## Финансовые показатели

- **Поступления за вычетом возвратов**: вручную внесённые операции `received - refunded`.
- **Себестоимость завершённых заказов**: сумма снимков учётной себестоимости для `completed`.
- **Валовая маржа завершённых заказов**: цена всех завершённых заказов минус их учётная себестоимость. Это **не бухгалтерская прибыль**: не включены аренда, налоги, доставка и другие расходы.
- В Excel рядом с каждым заказом показаны полученная сумма и остаток к оплате. Финансовые поступления и стоимость завершённых заказов выводятся отдельно.
- **Стоимость неотменённых заказов**: объём принятых обязательств, **не** полученная выручка.

## Excel без Telegram и резервное копирование

```bash
# Без токена и без запуска бота — выдаёт Excel (файл не перезаписывается):
python -m atelier.export reports/report-2026-10-31.xlsx
# Согласованная резервная копия SQLite с PRAGMA integrity_check:
python -m atelier.backup backups/atelier-2026-10-31.sqlite3
```

Файл резервной копии не перезаписывается повторным запуском. Создавайте копии **в защищённом месте**, не в публичном Git-репозитории. Проверена целостность резервных копий SQLite.

## Публикация в GitHub

Если проект скачан в виде ZIP, он содержит **только исходники**, без папки `.git`. Для публикации с сохранением истории сначала распакуйте отдельный `atelier-telegram-shop.git.bundle` (два скачанных файла должны находиться рядом), затем в PowerShell выполните:

```powershell
git clone .\atelier-telegram-shop.git.bundle atelier-telegram-shop
cd .\atelier-telegram-shop
```

Репозиторий должен быть **приватным** по умолчанию: в Git никогда не добавляются токены и базы данных. Готова автоматизация однократного создания репозитория и публикации уже зафиксированного коммита:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/publish-to-github.ps1
```

Требуется авторизованный GitHub CLI `gh`. Скрипт проверяет владельца `Ai-b0ss`, чистоту рабочего дерева и приватность созданного репозитория, не перезаписывает существующий репозиторий и не использует force-push. При отсутствии доступа к CLI файлы можно загрузить через подключённую GitHub-интеграцию в уже созданный репозиторий.

## Автономная демонстрация без Telegram

Чтобы получить **отдельную синтетическую базу** (три заказа разных статусов: выполненный, в пошиве и отменённый с возвратом) и Excel-отчёт, выполните:

```bash
python -m atelier.demo out/demo
```

Команда не использует реальных покупателей, не подключается к Telegram и не перезаписывает уже существующие файлы `out/demo/demo.sqlite3` и `out/demo/demo_report.xlsx`. Это удобно для учебной защиты и первичного знакомства с отчётностью. Для запуска нужны зависимости из `requirements.txt` (сам `aiogram` для этой команды не импортируется).

## Проверка

```bash
pip install -r requirements-dev.txt
python -m pytest -q
python -m compileall -q atelier
```

Для тестового прогона не требуется реальный Telegram-бот. Дополнительные тесты обработчиков используют имитацию интерфейса `aiogram`; они не подтверждают совместимость с реальным Telegram API. Живая приёмка требует токен, установленный `aiogram` и доступность Telegram.

## Безопасность и эксплуатация

- `.env` и SQLite-файлы исключены из Git. Никогда не публикуйте токен бота или реальные персональные данные клиентов.
- Не выводите отчёты и резервные копии в публичный доступ: они содержат контакты и мерки клиентов.
- Доступ к админ-командам проверяется по Telegram ID, а не по имени пользователя. Бот обрабатывает только личные чаты.
- В Excel пользовательские строки защищены от инъекции формул.
- Храните резервные копии базы и ограничьте доступ к папке `data`. Сроки хранения и согласие на обработку персональных данных необходимо определить перед реальной эксплуатацией.
- Пользовательские заказы не содержат платёжных реквизитов. Команда `/forgetme` обезличивает закрытые заказы и очищает свободные платёжные примечания; идентификаторы банковских операций остаются в журнале для сверки. Для реальной эксплуатации необходимы сроки хранения, политика обработки данных и процедура удаления старых копий.
- Онлайн-платежи, производственная калькуляция и масштабирование на несколько ботов не входят в MVP.
