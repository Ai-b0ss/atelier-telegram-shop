# Проверка MVP

**Дата:** 31 октября 2026. **Окружение:** Linux для исходных доменных тестов; Windows 10, Python 3.13.9, aiogram 3.31.0 и изолированное .venv для повторной проверки.

## Автоматические тесты

- 39 из 39 — успешно (без подключения к Telegram API; обработчики проверены как через имитации, так и через настоящую маршрутизацию aiogram 3).
- Дополнительно проверены: блокировка устаревшей сметы при повторной отправке **той же цены**, конкурентное подтверждение/отклонение сметы, проверка идентификатора покупателя, блокировка дублирования банковского номера операции, миграция прежней SQLite-схемы, очистка текста платежных примечаний и целостность синтетической демонстрации.
- Проверены: тестовые категории, корзина, атомарное списание остатков, конкурентная покупка единственного экземпляра, корректная отмена до и после отправки, одновременные отмены, последовательности статусов, запрещённые переходы, ручной учёт оплаты/возвратов, индивидуальные сметы, защита всех пользовательских полей Excel от интерпретации как формул, неизменность цены в созданном заказе, ограничения БД, парсинг денежных сумм, структура и значения отчёта, обезличивание сведений, резервное копирование и автономный экспорт.
- Исходный код скомпилирован через `compileall` без синтаксических ошибок.
- BPMN-файлы проверяются структурно (узлы, ссылки потоков и развилки) скриптом `scripts/verify_release.py` после Git-коммита.
- Добавлен воспроизводимый генератор синтетической базы и Excel-отчёта: `python -m atelier.demo out/demo`. Использует три заказа разных статусов и четыре ручные записи оплаты/возврата; реальных клиентских данных нет.
- Проверены функции Telegram-обработчиков на искусственных сообщениях (офлайн), включая оплату доступа к `/report`, создание заказа из корзины, генерацию кнопок сметы и защиту от старых кнопок. Дополнительно проверена настоящая маршрутизация aiogram 3: FSM оформления заказа, заявки на индивидуальный пошив, согласование и устаревание смет, ограничение администрирования, Excel и отклонение сообщений из групп. Сеть Telegram подменена только на уровне вызовов Bot API.

## Локальный замер производительности

Один запуск: **50** последовательных заказов по одной позиции, каждый с созданием клиента, корзиной, оформлением, записью оплаты и тремя сменами статуса.

- Все 50 сценариев завершились без ошибок: **0,795 секунды** суммарно, в среднем **15,9 мс** на сценарий операций БД.
- Excel-отчёт после 50 заказов: **13 109 байт**, формирование **25,0 мс**.

Эти показатели — **локальный микробенчмарк**, а не гарантия скорости под нагрузкой. Они не учитывают сеть Telegram, доставку уведомлений, работу VPS, реальные операции менеджера или юридическую и бухгалтерскую проверку.

## Ограничения локальной проверки

Замер выполнялся в изолированном процессе с 50 заказами на временной SQLite-базе. Указанные временные показатели зависят от машины и не распространяются на Telegram API, VPS и действия менеджера.

## Реальная проверка Telegram API 1 ноября 2026

Запущен локальный polling-бот @atelier_customwear_2611_bot. Через Telegram Desktop подтверждены: /start, каталог, выбор варианта, корзина, создание заказа №1, уведомление администратору, смена статуса на canceled и выдача файла Excel. Повторное чтение SQLite показало восстановление остатка и отсутствие финансовых поступлений. Включён режим DEMO_MODE=1; реальных клиентов и денег нет.

## Что остаётся непроверенным

- Живой тест проведён с одной Telegram-учётной записью. Отдельная приёмка с настоящим вторым покупателем и полный сценарий согласования индивидуальной сметы ещё не проводились.
- Постоянный запуск в Docker или на VPS: движок Docker на проверенном Windows-ПК не был доступен.
- Пользовательская приёмка реальными покупателями и менеджером, включая скорость подтверждения заказов.
- Реальная калькуляция себестоимости и юридическая проверка обработки персональных данных.

## GitHub Actions

После публикации репозитория как публичного проверка прошла на Python 3.11, 3.12 и 3.13. Тесты запускаются на каждом push/PR.

**Вывод:** 45 автоматизированных тестов успешно проверяют локальную бизнес-логику и регистрацию/маршрутизацию реального aiogram. Для полноценной эксплуатации необходимы реальные товары, второй тестовый покупатель, политика обработки данных и постоянный хостинг.
