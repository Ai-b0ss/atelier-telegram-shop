# Atelier Telegram Shop — бот для авторской одежды

Учебный, но запускаемый MVP продажи авторской одежды через Telegram: **каталог → корзина → оформление заказа**, индивидуальные заявки на пошив, административные статусы, ручной учёт финансовых операций и Excel-отчёты.

## Roadmap развития

**[ROADMAP.md — план до готового ателье](ROADMAP.md)** · [актуальные задачи и зависимости — GitHub #24](https://github.com/Ai-b0ss/atelier-telegram-shop/issues/24).

Цель v1: настоящие товары и индивидуальный пошив через Telegram Mini App **без встроенных онлайн-платежей**. Работа разбита на короткие самостоятельные ИИ-пакеты с тестами и ревью: надёжность уведомлений и данных, профессиональный редизайн, импорт ассортимента, сквозная приёмка. Демо остаётся закрытым для настоящих заказов до готовности бизнеса и отдельного разрешения.

## Текущая демонстрация в Telegram

**[Открыть Telegram-бота](https://t.me/atelier_customwear_2611_bot)**. Бот создан и проверен на настоящем Telegram API. Работает с вымышленным ассортиментом в режиме `DEMO_MODE=1`. Тестовые заказы доступны только настроенному администратору; остальным пользователям бот отвечает, что магазин ещё не принимает заказы. С 1 ноября демо работает в Cloudflare Workers + D1 и не зависит от включённого ПК. Настоящих клиентов, платежей и реальных товаров нет.

В первоначальном локальном прототипе цепочка «каталог → корзина → заказ → уведомление → отмена → восстановление остатка» проверялась на синтетических данных без реальных денег. В работающем облачном боте подтверждены команды, XLSX, выбор товара и добавление в корзину; независимая многопользовательская покупка с отменой **ещё не подтверждена**. [Протокол с границами проверки](docs/redesign-qa-and-university-status.md).

## Бесплатный облачный хостинг Cloudflare — работает

**[@atelier_customwear_2611_bot](https://t.me/atelier_customwear_2611_bot)**
подключён к Cloudflare Workers через Telegram webhook, а каталог и тестовые
заказы хранятся в отдельной постоянной базе D1. Хостинг не зависит от
включённого Windows-компьютера, но действуют квоты бесплатного тарифа.

1 ноября реальный Telegram Desktop получил ответы на `/start` и `/report`
от облачной версии, XLSX доставлен. Telegram `getWebhookInfo` и Cloudflare
`/health` подтверждены, ожидающих обновлений нет. Windows-бот остановлен,
автозапуск задачи `AtelierTelegramDemo` отключён, конфликтов polling нет.

Секреты передаются напрямую из локального `.env` в Cloudflare по официальному
протоколу Wrangler через stdin, без вывода значений. Доступ покупателей
по-прежнему ограничен демонстрационным режимом; настоящих товаров и платежей нет.

[Инструкция по Cloudflare, проверкам и откату](cloudflare/README.md).

## Исправленная логика отмены и возврата

До отправки заказ можно отменить с автоматическим восстановлением
зарезервированных остатков. После статуса `shipped` отмена сама
не прибавляет товар на склад: только отдельная операция `/return ID ПОЛУЧЕНО`
или подтверждение в панели управления фиксирует физическое получение.
Транзакционный триггер и уникальный акт `inventory_return_receipts`
запрещают двойное пополнение склада. В демо это синтетические операции.

Полные модели и пояснения: [бизнес-процессы](docs/business-process.md),
[структура данных](docs/data-model.md),
[инженерный отчёт](docs/project-report.md),
[протокол испытаний](docs/test-report.md).

## Возможности

- Категории, товары, размеры, цвета и складские остатки; фотографии по Telegram `file_id`, если указаны в базе.
- Корзина с проверкой наличия и атомарным оформлением заказа (SQLite).
- Заявки на индивидуальный пошив с мерками и пожеланиями; согласование точной версии сметы, защищённое от устаревших кнопок и гонок.
- Администраторские команды для статусов, смет, записи оплат и возвратов; необязательный уникальный идентификатор платежа для защиты от двойной записи.
- Excel (.xlsx): сводные показатели, заказы, платежи, остатки и учётная себестоимость.
- 48 Python-тестов и отдельные Node-тесты облачного Worker, включая маршрутизацию настоящего aiogram без сети и проверки обработчиков бота, финансов, остатков, конкуренции, приватности, резервных копий и выгрузки.
- Меню фильтрации заказов, кнопки изменения статусов и `/stats` для администратора.
- `/privacy`, `/forgetme`: информация о данных и запрос обезличивания после закрытия заказов.
- Автономный экспорт в Excel и согласованные резервные копии SQLite (без Telegram).

## Запуск

Требуется **Python 3.11+** и токен Telegram от @BotFather.

```bash
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell:
# .venv\\Scripts\\Activate.ps1
pip install -r requirements.txt
```

Бот **сам читает** локальный файл `.env` при запуске командой `python -m atelier` (внешние переменные окружения имеют приоритет). Скопируйте `.env.example` в `.env`. Заполните **BOT_TOKEN**, **ADMIN_IDS** (Telegram ID администратора через запятую), при желании **DATABASE_PATH**. Для запуска достаточно:

```bash
python -m atelier.seed
python -m atelier
```

Или через Docker Compose (после создания `.env`):

```bash
docker compose run --rm bot python -m atelier.seed
docker compose up -d --build
```

**Важно:** демонстрационные товары вымышленные. Перед продажей замените ассортимент и цены в SQLite, укажите администратора и настройте хостинг для круглосуточного запуска. Для изменения каталога предусмотрена консольная утилита `python -m atelier.manage` (см. ниже), для облачной версии есть графическая админ-панель на /admin.

## Удобный запуск на Windows

В локальной рабочей копии `C:\Users\user\Documents\atelier-telegram-shop` предусмотрены два PowerShell-скрипта:

```powershell
# Один раз: ввод токена скрыт, пароль не появляется в истории команд.
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-bot.ps1
# Каждый последующий запуск:
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-bot.ps1
```

`setup-bot.ps1` сохраняет `BOT_TOKEN` и `ADMIN_IDS` **только** в локальном `.env`, предварительно проверяя исключение файла из Git; существующий файл никогда не перезаписывает. `start-bot.ps1` использует проектное `.venv` и не выводит секреты. Бот считывает `.env` самостоятельно.

Перед демонстрацией проверьте ассортимент: `python -m atelier.manage list`. Наполнение через `python -m atelier.seed` создаёт вымышленные демонстрационные товары, **не настоящий товарный каталог**. Для работы в Telegram необходимо получить настоящий токен у BotFather.

## Автозапуск и восстановление на Windows

**Архивный резервный вариант:** после перехода на Cloudflare задание Windows
`AtelierTelegramDemo` отключено. Не включайте его одновременно с webhook.



Архивный локальный режим использовал задачу Windows `AtelierTelegramDemo`,
запускавшую `python -m atelier.supervisor` после входа в Windows.
**Сейчас задача отключена**, поскольку Cloudflare принимает Telegram webhook.
Не запускайте локальный polling одновременно с облачным webhook.
Процесс поднимает Telegram-бота, повторяет запуск после сбоя с ограниченной
задержкой и не допускает двух экземпляров polling для одной базы.

- Состояние задания: `Get-ScheduledTask -TaskName AtelierTelegramDemo`
- Текущий запуск: `Start-ScheduledTask -TaskName AtelierTelegramDemo`
- Остановка: `Stop-ScheduledTask -TaskName AtelierTelegramDemo`
- Отключение автозапуска: `Disable-ScheduledTask -TaskName AtelierTelegramDemo`
- Логи: `data/logs/supervisor.log` (ротация, не публикуйте)
- Проверенные резервные копии SQLite: `data/backups/atelier-*.sqlite3`.
  Новая копия создаётся при запуске и каждые 6 часов работы; старые копии **не удаляются автоматически**.
- Создать дополнительную копию: `python -m atelier.maintenance`

Для Windows также включена защита дочерних процессов через Job Object: при остановке задания завершается и бот, без «зависших» экземпляров. Это проверено реальной остановкой и повторным запуском Планировщика.

Задание рассчитано на локальное демо, а **не** на работу 24/7:
оно не выполняется при выключенном ПК или без входа пользователя.
Для реальных клиентов нужен отдельный хостинг и согласованная политика
хранения/удаления копий. По умолчанию `DEMO_MODE=1` даже если этот
параметр отсутствует; `DEMO_MODE=0` переводит проект в боевой режим
только после подготовки реального ассортимента и юридических документов.

## Настройка каталога

```bash
python -m atelier.manage list
python -m atelier.manage category "Платья"
python -m atelier.manage product 4 "Платье с вышивкой" "Лён, ручная вышивка"
python -m atelier.manage variant 4 DRESS-S-BLUE S синий 9500 4200 5
python -m atelier.manage stock 4 7
python -m atelier.manage deactivate 4
```

Числа `4` — примеры идентификаторов: после создания посмотрите фактически возвращённый ID. Цены указываются в рублях. Загрузка фото использует Telegram `file_id`: `python -m atelier.manage photo <product_id> <file_id>`.

## Пользовательские сценарии

`/start` → категории → изделие → размер/цвет → корзина → оформление → имя, контакт, адрес / самовывоз.

`/start` → «Индивидуальный пошив» → описание → мерки → контакты → заявка. Стоимость такого заказа изначально нулевая и **не означает бесплатный пошив**: менеджер задаёт смету, после чего клиент может принять или отклонить предложение кнопкой в Telegram. Устаревшие кнопки с прежней ценой не работают.

`/cancel` прерывает ввод. «Мои заказы» показывает только заказы текущего Telegram-пользователя.

## Команды администратора

| Команда | Назначение |
|---|---|
| `/admin` | подсказка |
| `/orders` | последние 30 заказов |
| `/orders new` | заказы выбранного статуса |
| `/order 12` | детали заказа и контактные данные для менеджера |
| `/quote 12 15000 8500` | смета индивидуального заказа №12: цена и себестоимость в рублях |
| `/status 12 confirmed` | перевод заказа в разрешённый следующий статус |
| `/payment 12 received 3000 BANK-001` | **ручная запись** подтверждённого поступления 3000 ₽; `BANK-001` — уникальный номер операции (необязательно, но рекомендуется) |
| `/payment 12 refunded 3000` | **ручная запись** подтверждённого возврата 3000 ₽ |
| `/report` | Excel-выгрузка |
| `/stats` | Денежные поступления, завершённые продажи, себестоимость и валовая маржа |

Статусы: `new`, `confirmed`, `in_production`, `ready`, `shipped`, `completed`, `canceled`.

**Бот не принимает реальную оплату и не переводит деньги.** Команда `/payment` вносит запись только после сверки с реальным платежом. Уникальный банковский номер препятствует двойному учёту одной операции; без него администратор должен сам проверить дубликаты. Нельзя отменить заказ с невозвращённой оплатой.

## Финансовые показатели

- **Поступления за вычетом возвратов**: вручную внесённые операции `received - refunded`.
- **Себестоимость завершённых заказов**: сумма снимков учётной себестоимости для `completed`.
- **Валовая маржа завершённых заказов**: цена всех завершённых заказов минус их учётная себестоимость. Это **не бухгалтерская прибыль**: не включены аренда, налоги, доставка и другие расходы.
- В Excel рядом с каждым заказом показаны полученная сумма и остаток к оплате. Финансовые поступления и стоимость завершённых заказов выводятся отдельно.
- **Стоимость неотменённых заказов**: объём принятых обязательств, **не** полученная выручка.

## Excel без Telegram и резервное копирование

```bash
# Без токена и без запуска бота — выдаёт Excel (файл не перезаписывается):
python -m atelier.export reports/report-2026-10-31.xlsx
# Согласованная резервная копия SQLite с PRAGMA integrity_check:
python -m atelier.backup backups/atelier-2026-10-31.sqlite3
```

Файл резервной копии не перезаписывается повторным запуском. Создавайте копии **в защищённом месте**, не в публичном Git-репозитории. Проверена целостность резервных копий SQLite.

## Публикация в GitHub

Если проект скачан в виде ZIP, он содержит **только исходники**, без папки `.git`. Для публикации с сохранением истории сначала распакуйте отдельный `atelier-telegram-shop.git.bundle` (два скачанных файла должны находиться рядом), затем в PowerShell выполните:

```powershell
git clone .\atelier-telegram-shop.git.bundle atelier-telegram-shop
cd .\atelier-telegram-shop
```

Репозиторий уже **публичный**: https://github.com/Ai-b0ss/atelier-telegram-shop. В Git хранится только код и документация; не коммитьте токены, реальные данные клиентов, базы SQLite или отчёты с персональными данными. При необходимости скрипт ниже позволяет создать новый публичный репозиторий из локального Git-клона:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/publish-to-github.ps1
```

Требуется авторизованный GitHub CLI `gh`. Скрипт проверяет владельца `Ai-b0ss`, чистоту рабочего дерева и публичность созданного репозитория; существующий репозиторий не перезаписывает и не использует force-push. Для обновления уже опубликованного проекта достаточно обычного `git push`.

## Автономная демонстрация без Telegram

Чтобы получить **отдельную синтетическую базу** (три заказа разных статусов: выполненный, в пошиве и отменённый с возвратом) и Excel-отчёт, выполните:

```bash
python -m atelier.demo out/demo
```

Команда не использует реальных покупателей, не подключается к Telegram и не перезаписывает уже существующие файлы `out/demo/demo.sqlite3` и `out/demo/demo_report.xlsx`. Это удобно для учебной защиты и первичного знакомства с отчётностью. Для запуска нужны зависимости из `requirements.txt` (сам `aiogram` для этой команды не импортируется).

## Проверка

```bash
pip install -r requirements-dev.txt
python -m pytest -q
python -m compileall -q atelier
```

Для тестового прогона не требуется реальный Telegram-бот. Дополнительные тесты обработчиков используют имитацию интерфейса `aiogram`; они не подтверждают совместимость с реальным Telegram API. Живая приёмка требует токен, установленный `aiogram` и доступность Telegram.

## Безопасность и эксплуатация

- `.env` и SQLite-файлы исключены из Git. Никогда не публикуйте токен бота или реальные персональные данные клиентов.
- Не выводите отчёты и резервные копии в публичный доступ: они содержат контакты и мерки клиентов.
- Доступ к админ-командам проверяется по Telegram ID, а не по имени пользователя. Бот обрабатывает только личные чаты.
- В Excel пользовательские строки защищены от инъекции формул.
- Храните резервные копии базы и ограничьте доступ к папке `data`. Сроки хранения и согласие на обработку персональных данных необходимо определить перед реальной эксплуатацией.
- Пользовательские заказы не содержат платёжных реквизитов. Команда `/forgetme` обезличивает закрытые заказы и очищает свободные платёжные примечания; идентификаторы банковских операций остаются в журнале для сверки. Для реальной эксплуатации необходимы сроки хранения, политика обработки данных и процедура удаления старых копий.
- Онлайн-платежи, производственная калькуляция и масштабирование на несколько ботов не входят в MVP.
